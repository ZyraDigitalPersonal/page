Tutorial: del formulario de tu web a Google Sheets y un aviso al equipo, con Make

Es la primera automatización que montamos en casi cualquier negocio: cada vez que alguien rellena el formulario de contacto, la solicitud se guarda en una hoja de cálculo ordenada y alguien del equipo recibe un aviso. Se monta en una tarde y evita el problema más común de los formularios: mensajes que llegan a un buzón que nadie mira. Usaremos Make y Google Sheets, pero la idea es la misma en Zapier o n8n.

Antes de empezar. Necesitas una cuenta de Make a nombre del negocio, una cuenta de Google con acceso a la hoja y poder modificar el formulario de tu web (o pedírselo a quien la mantenga). Los nombres de los botones pueden cambiar ligeramente con las actualizaciones de Make; la ayuda oficial siempre tiene la versión vigente.

El esquema

  1. La web envía los datos del formulario a una dirección de Make (un webhook).
  2. Make añade una fila en Google Sheets con esos datos y la fecha.
  3. Make envía un aviso al equipo (email, Slack o similar).
  4. Si algo falla, Make guarda la ejecución para reintentarla y avisa.

Paso 1: prepara la hoja

Crea una hoja en Google Sheets con una primera fila de encabezados. Por ejemplo: Fecha, Nombre, Email, Teléfono, Servicio, Mensaje, Estado. La columna Estado la rellenará el equipo a mano (“pendiente”, “respondido”, “presupuesto enviado”) y convierte la hoja en una lista de seguimiento muy simple.

Comparte la hoja solo con quien la necesita: contiene datos personales.

Paso 2: crea el webhook en Make

  1. Crea un escenario nuevo y añade como primer módulo Webhooks → Custom webhook.
  2. Pulsa Add, ponle un nombre reconocible (“Formulario web”) y copia la dirección que genera Make. Trátala como una contraseña: quien la tenga puede enviarte datos.
  3. Deja el módulo esperando datos (Make lo indica con “determine data structure”) y envía un formulario de prueba desde tu web. Make detectará los campos automáticamente.

Paso 3: envía el formulario a Make desde el servidor

Se puede apuntar el formulario HTML directamente a la dirección del webhook, pero no lo recomendamos: la dirección queda visible en el código de la página y cualquiera podría usarla para llenar tu hoja de spam. Es mejor que tu servidor reciba el formulario, haga sus comprobaciones (campos obligatorios, protección contra bots) y después lo reenvíe. En una web con PHP, el reenvío cabe en pocas líneas:

<?php
// Después de validar el formulario...
$datos = [
  'nombre'   => $nombre,
  'email'    => $email,
  'telefono' => $telefono,
  'servicio' => $servicio,
  'mensaje'  => $mensaje,
  'fecha'    => date('c'),
];
$ch = curl_init(MAKE_WEBHOOK_URL);          // guárdala fuera del código público
curl_setopt_array($ch, [
  CURLOPT_POST           => true,
  CURLOPT_HTTPHEADER     => ['Content-Type: application/json'],
  CURLOPT_POSTFIELDS     => json_encode($datos),
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_TIMEOUT        => 10,
]);
$ok = curl_exec($ch) !== false && curl_getinfo($ch, CURLINFO_HTTP_CODE) < 300;
curl_close($ch);
// Si $ok es false, guarda la solicitud en el servidor o envíate un email:
// el formulario nunca debe perderse porque Make no responda.

Lo importante está en el último comentario: el formulario debe seguir funcionando aunque Make esté caído. Por eso el envío a Make es un paso más, no el único lugar donde se guarda la solicitud.

Paso 4: añade la fila en Google Sheets

  1. Añade el módulo Google Sheets → Add a row y conecta la cuenta de Google del negocio.
  2. Elige la hoja y la pestaña. Make mostrará las columnas según los encabezados que creaste.
  3. Asigna a cada columna el campo correspondiente del webhook (arrastrando los valores del primer módulo). Deja Estado con el texto fijo “pendiente”.

Paso 5: avisa al equipo

Añade un tercer módulo para el aviso. Las opciones más habituales son Email → Send an email, Gmail → Send an email o Slack → Create a message. Un buen aviso es corto y permite actuar sin abrir la hoja:

Nueva solicitud de {{nombre}} ({{servicio}})
Teléfono: {{telefono}} · Email: {{email}}
"{{mensaje}}"

Si atendéis por WhatsApp, también se puede enviar el aviso por WhatsApp, pero requiere la API oficial; lo explicamos en la guía sobre WhatsApp Business y chatbots.

Paso 6: prepara el escenario para los fallos

Todo flujo falla alguna vez: Google pide volver a conectar la cuenta, alguien cambia el nombre de una columna o llega un dato raro. Tres ajustes evitan perder solicitudes:

  • En la configuración del escenario, activa la opción de guardar las ejecuciones incompletas. Si un paso falla, la ejecución queda guardada para revisarla y reintentarla.
  • Configura las notificaciones de error de Make para que lleguen a un email que alguien lea.
  • No cambies los encabezados de la hoja sin revisar después el módulo de Google Sheets.

Paso 7: prueba como lo haría un cliente

  1. Envía un formulario normal y comprueba la fila y el aviso.
  2. Envía uno con tildes, eñes y un mensaje largo con saltos de línea.
  3. Envía uno dejando vacíos los campos opcionales.
  4. Desconecta temporalmente el escenario y envía otro: tu web debe seguir respondiendo bien y guardar la solicitud por su lado.

Cuando todo funcione, activa el escenario con la programación “inmediatamente” para que procese cada formulario en cuanto llega.

Protección de datos

Con este flujo, los datos del formulario pasan por Make y se guardan en Google. Ambas empresas actúan como encargadas del tratamiento: menciónalas en tu política de privacidad y no guardes en la hoja más datos de los necesarios. Lo explicamos en Qué tiene que llevar por ley la web de un negocio.
